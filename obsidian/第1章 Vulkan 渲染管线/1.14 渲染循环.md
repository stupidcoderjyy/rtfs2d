# 1.14 渲染循环

#### 目标
在谜题 1.13 的基础上，实现渲染循环将清屏指令提交到 GPU 并呈现到窗口，实现：
1. 窗口每帧清屏为深蓝灰色 `(0.1, 0.15, 0.2)`，FPS 由 V-Sync 控制
2. 循环中正确处理同步：acquire → submit → present
3. 窗口关闭后等待 GPU 完成所有工作再退出

#### 规则
- 循环结构 — 在 `Show()` 中将原来的空轮询 `while (!glfwWindowShouldClose(window_)) { glfwPollEvents(); }` 替换为完整的渲染循环。退出条件不变（用户点击关闭按钮）。循环结束后调用 `device_->waitIdle()` 确保 GPU 完成所有工作，再让 RAII 对象析构

- `device_->waitForFences(**in_flight_fences_[current_frame_], VK_TRUE, UINT64_MAX)` — 等待当前帧的 fence 变为 signaled。`**` 的双层解引用：第一层从 `unique_ptr` 取 `vk::raii::Fence&`，第二层取底层的 `vk::Fence` 句柄

- `swapchain_->acquireNextImage(UINT64_MAX, **image_available_semaphores_[current_frame_])` — 从交换链获取下一张可用的图像。返回值是 `std::pair<vk::Result, uint32_t>`，其中 `uint32_t` 是交换链图像的索引（即本次应渲染 `command_buffers_[image_index]` 和 `framebuffers_[image_index]`）。第二个参数是一个 semaphore，acquire 完成后自动 signal

- `device_->resetFences(**in_flight_fences_[current_frame_])` — 将 fence 重置为 unsignaled 状态

- `vk::SubmitInfo` — 提交命令缓冲到队列。需要设置的字段：
  - `waitSemaphoreCount = 1`，`pWaitSemaphores` — 指向 `&**image_available_semaphores_[current_frame_]`
  - `pWaitDstStageMask` — `vk::PipelineStageFlags::eColorAttachmentOutput`
  - `commandBufferCount = 1`，`pCommandBuffers` — 指向 `&command_buffers_[image_index]`（image_index 即上一步 acquire 返回的索引）
  - `signalSemaphoreCount = 1`，`pSignalSemaphores` — 指向 `&**render_finished_semaphores_[current_frame_]`

- `graphics_queue_->submit(submit_info, **in_flight_fences_[current_frame_])` — 提交命令缓冲，完成后 signal fence

- `vk::PresentInfoKHR` — 将渲染结果呈现到窗口。`waitSemaphoreCount = 1`，`pWaitSemaphores` 指向 `&**render_finished_semaphores_[current_frame_]`；`swapchainCount = 1`，`pSwapchains` 指向 `&**swapchain_`；`pImageIndices` 指向 `image_index`

- `present_queue_->presentKHR(present_info)` — 呈现图像

- `current_frame_ = (current_frame_ + 1) % kMaxFramesInFlight` — 推进帧索引
