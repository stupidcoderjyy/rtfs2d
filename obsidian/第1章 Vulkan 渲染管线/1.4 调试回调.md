# 1.4 调试回调

#### 目标
在谜题 1.3 的基础上，为 Vulkan 实例注册调试回调，实现：
1. 验证层的所有消息（Info / Warning / Error）以 `[Vulkan]` 前缀打印到控制台
2. 回调在 instance 创建和销毁阶段也处于激活状态
3. 程序退出前正确销毁 `VkDebugUtilsMessengerEXT`，无 validation error

#### 规则
- `VkDebugUtilsMessengerCreateInfoEXT` — 配置调试回调的结构体。`sType = VK_STRUCTURE_TYPE_DEBUG_UTILS_MESSENGER_CREATE_INFO_EXT`；`messageSeverity` 组合 `VK_DEBUG_UTILS_MESSAGE_SEVERITY_WARNING_BIT_EXT | VK_DEBUG_UTILS_MESSAGE_SEVERITY_ERROR_BIT_EXT`；`messageType` 组合 `VK_DEBUG_UTILS_MESSAGE_TYPE_GENERAL_BIT_EXT | VK_DEBUG_UTILS_MESSAGE_TYPE_VALIDATION_BIT_EXT | VK_DEBUG_UTILS_MESSAGE_TYPE_PERFORMANCE_BIT_EXT`；`pfnUserCallback` 指向回调函数
- `PFN_vkDebugUtilsMessengerCallbackEXT` — 回调函数签名：`VKAPI_ATTR VkBool32 VKAPI_CALL callback(VkDebugUtilsMessageSeverityFlagBitsEXT, VkDebugUtilsMessageTypeFlagsEXT, const VkDebugUtilsMessengerCallbackDataEXT*, void*)`。返回 `VK_FALSE` 表示不中断调用
- `pNext` 链式注册 — 将 `VkDebugUtilsMessengerCreateInfoEXT` 的地址赋给 `VkInstanceCreateInfo::pNext`。这确保 instance 创建和销毁期间的消息也能被回调捕获（若仅在 `vkCreateInstance` 之后单独调用 `vkCreateDebugUtilsMessengerEXT`，会漏掉这两个阶段的消息）
- `vkCreateDebugUtilsMessengerEXT` — 扩展函数，需通过 `vkGetInstanceProcAddr(instance, "vkCreateDebugUtilsMessengerEXT")` 动态加载。仅在验证层可用时调用。若函数指针为 `nullptr`，跳过创建
- `vkDestroyDebugUtilsMessengerEXT` — 对应的销毁函数，同样通过 `vkGetInstanceProcAddr` 加载。必须在 `vkDestroyInstance` 之前调用
- 回调函数内格式化消息 — 使用 `callbackData->pMessage` 获取消息文本，输出格式：`std::cerr << "[Vulkan] " << callbackData->pMessage << std::endl`
