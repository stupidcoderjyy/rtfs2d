# 第1章 Vulkan 渲染管线

**目标**：从空项目开始，用 GLFW + Vulkan 在屏幕上渲染一个可缩放的有色窗口。

每个谜题的产物是当前阶段可以编译运行的程序。从 1.1 到 1.15 渐进构建，最终得到一个响应窗口缩放、每帧清屏的 Vulkan 应用。

---

## 摘要

项目采用 CMake 构建系统，源码分为三层：顶层 `main.cpp` 作为程序入口，`src/` 下的 `rtfs2d_core` 静态库承载全部 Vulkan 逻辑，`test/` 提供 Google Test 单元测试骨架。核心类 `rtfs2d::Window` 封装了 GLFW 窗口管理和完整的 Vulkan 渲染管线，所有 GPU 资源通过 vulkan_hpp 的 RAII 类型（`vk::raii::Instance`、`vk::raii::Device`、`vk::raii::SwapchainKHR` 等）自动管理生命周期，无需手动调用销毁函数。

程序启动后依次完成以下阶段：初始化 GLFW 并创建无 OpenGL 上下文的窗口；创建 Vulkan 实例并注册调试回调（通过 `pNext` 链挂载，确保实例创建和销毁阶段的消息也被捕获）；创建窗口表面后枚举物理设备，选定首个支持 graphics/present 队列族和 swapchain 扩展的 GPU；从选定的物理设备创建逻辑设备并获取队列句柄；创建交换链时查询 surface 能力、选取 sRGB 格式和 FIFO 呈现模式；为每张交换链图像创建图像视图，建立渲染通道（含一个颜色附件的图形 subpass），然后为每个图像视图创建对应的帧缓冲。命令池以 `eResetCommandBuffer` 标志创建，按飞行帧数分配主命令缓冲，每帧在 `RecordCommands` 中重新录制清屏指令——先通过 image memory barrier 将图像转为颜色附件布局，再用随时间正弦变化的 RGB 颜色清屏，最后转回呈现布局。同步对象分为两组：与飞行帧绑定的 acquire semaphore 和 fence（数量为 `kMaxFramesInFlight`），以及与交换链图像绑定的 render semaphore（数量为 `swapchain_images_.size()`），前者防止 CPU 超前 GPU，后者防止 present 异步操作中的信号量冲突。

渲染循环在 `Show()` 中以 `glfwWindowShouldClose` 为退出条件运行：先等待当前帧 fence 完成以复用资源，然后从交换链 acquire 图像、录制命令缓冲、提交到 graphics 队列并 signal fence、最后 present 到窗口。窗口缩放通过 `glfwSetFramebufferSizeCallback` 监听，触发 `RecreateSwapChain()` 销毁并重建交换链、图像视图、帧缓冲和 render semaphore（通过 `setOldSwapchain` 传递旧交换链优化过渡）；窗口最小化时以 `glfwWaitEvents` 阻塞等待恢复。`acquireNextImage` 返回 `eErrorOutOfDateKHR` 时即时重建，`presentKHR` 返回 `eSuboptimalKHR` 或 `eErrorOutOfDateKHR` 时延迟到下一帧重建。循环结束后 `device_->waitIdle()` 确保 GPU 完成所有工作，再让 RAII 按声明逆序安全析构所有 Vulkan 资源。
