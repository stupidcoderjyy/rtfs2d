# 9.1 管线创建工厂

#### 目标
在[[第8章 流场可视化/章节总览|第8章]]的基础上，创建 `ComputeShaderTask`（封装 bindPipeline → bindDescriptorSets → pushConstants → dispatch 的四步链式接口）和 `ComputeShaderTaskFactory`（通过 Builder 模式统一创建计算管线），将 `FluidSolvers` 从直接持有管线/布局对象改为持有 `ComputeShaderTask`。实现：
1. `FluidSolvers` 不再持有任何 `pipeline_*` / `layout_*` 成员，改为持有 `ComputeShaderTask` 的 `unique_ptr`
2. 所有调度（`vulkan_hpp::CommandBuffer` 上的 `bindPipeline`/`bindDescriptorSets`/`pushConstants`/`dispatch`）统一到 `ComputeShaderTask` 的链式接口中

#### 规则
1. 创建 `src/compute_pipeline_factory.h`
    1. 声明 `class ComputeShaderTask`——封装单个计算任务的一次调度
    2. `Begin(const vk::CommandBuffer& cb, const vk::raii::DescriptorSet& ds)` 返回 `*this`：内部调用 `cb.bindPipeline` + `cb.bindDescriptorSets`，保存 `cb` 的指针
    3. 模板方法 `PushConstant<T>(values, offset=0)` 返回 `*this`：调用 `cb_->pushConstants<T>` 推送数据
    4. `End(uint32_t unit_size)`：调用 `cb_->dispatch((unit_size+127)/128, 1, 1)` 并置空 `cb_`
    5. 私有成员：`unique_ptr<vk::raii::Pipeline> pipeline_`、`shared_ptr<vk::raii::PipelineLayout> layout_`、`const vk::CommandBuffer* cb_`
    6. 声明 `namespace internal { class ComputeShaderTaskBuilder { ... }; }`——Builder 负责从着色器路径构建 `ComputeShaderTask`
    7. `ComputeShaderTaskBuilder` 模板方法 `AppendSpecializationConst<T>(initializer_list)`：遍历每个值，用 `AppendDataToBytesVec<T>` 追加 specialization constant 字节，同时构造 `SpecializationMapEntry` 数组（自动递增 constant_id）
    8. `SetPipelineLayout(shared_ptr<vk::raii::PipelineLayout>)`：设置管线布局；`SetPushConstSize(uint32_t)`：设置 push constant 大小
    9. `Build()` 方法：调用 `dm_->LoadShader` 获取着色器模块 → 构造 `PipelineShaderStageCreateInfo` → 若 `spec_const_entries_` 非空则设置 specialization info → 若 `push_const_size_` 非 0 则 `CreatePipelineLayout()` 创建带 push constant 的独立布局 → 调用 `dm_->device().createComputePipeline(nullptr, cp_ci)` → 返回 `unique_ptr<ComputeShaderTask>`
    10. `CreatePipelineLayout()`：构造 `PushConstantRange`（offset=0, size=push_const_size_）→ `PipelineLayoutCreateInfo`（setLayoutCount=1, pSetLayouts 指向 `cc_->descriptor_set_layout()`）→ `layout_ = make_shared<vk::raii::PipelineLayout>(...)`——覆盖原有共享布局
    11. 声明 `class ComputeShaderTaskFactory`：构造函数接收 `DeviceManager& dm, ComputeContext& cc`
    12. `Create(const string& shader_path) const` 返回 `ComputeShaderTaskBuilder`（按值返回，NRVO）：栈上构造 builder → 调用 `builder.SetPipelineLayout(cc_->pipeline_layout())` → `return builder`

2. 创建 `src/compute_pipeline_factory.cpp`
    1. 实现 `ComputeShaderTask` 构造函数：接收 `unique_ptr<vk::raii::Pipeline>` 和 `shared_ptr<vk::raii::PipelineLayout>`，移动构造
    2. 实现 `ComputeShaderTaskBuilder` 构造函数：保存 `dm_`、`cc_`、`shader_path_`
    3. 实现 `SetPipelineLayout`：`layout_ = layout;`
    4. 实现 `SetPushConstSize`：`push_const_size_ = size;`
    5. 实现 `Build()`
    6. 实现 `CreatePipelineLayout()`
    7. 实现 `ComputeShaderTaskFactory` 构造函数：保存 `dm_`、`cc_` 裸指针
    8. 实现 `Create()`：栈上构造 builder、设置共享布局、按值返回

3. 修改 `src/fluid_solvers.h`
    1. 删除所有 `std::unique_ptr<vk::raii::Pipeline> pipeline_*` 成员（共 14 个）
    2. 删除所有 `std::unique_ptr<vk::raii::PipelineLayout> layout_*` 成员（共 5 个）
    3. 删除所有 `Solve*` / `ComputeScalar` / `SmoothVelocity` / `AddDyeSource` 方法声明（共 14 个）
    4. 删除 `CreateSolverPipeline`、`CreateJacobiPipelines`、`CreateVorticitySolverPipeline`、`CreateComputeScalarPipeline`、`CreateDyeSourcePipeline` 方法声明
    5. 删除 `dm_`、`cc_`、`kWorkGroupSize` 私有成员
    6. 新增 `ComputeShaderTaskFactory factory_;` 成员
    7. 新增 14 个 `std::unique_ptr<ComputeShaderTask> task_*;` 成员（task_advection_、task_divergence_、task_diffusion_、task_poisson_、task_projection_、task_vorticity_、task_ibm_interpolate_、task_ibm_spread_、task_ibm_apply_force_、task_ibm_mask_、task_compute_scalar_、task_smooth_velocity_、task_dye_advection_、task_dye_source_）
    8. 新增 14 个 `ComputeShaderTask& task_*() const` getter

4. 修改 `src/fluid_solvers.cpp`
    1. 删除所有 `Solve*` 实现体（共约 200 行）
    2. 删除 `CreateSolverPipeline`、`CreateJacobiPipelines`、`CreateVorticitySolverPipeline`、`CreateComputeScalarPipeline`、`CreateDyeSourcePipeline` 实现体
    3. 构造函数改为：`FluidSolvers(DeviceManager& dm, ComputeContext& cc) : factory_(dm, cc) { ... }`
    4. 构造函数体内逐一创建 14 个 task：`task_advection_ = factory_.Create("shaders/advection.comp.spv").AppendSpecializationConst<uint32_t>({nx, ny}).Build();`——每个 task 根据是否需要 push constant 调用 `.SetPushConstSize(...)`（扩散/泊松/涡量/IBM/计算标量/染料源分别设置对应 size），不需要 push constant 的 task 不调用 SetPushConstSize（smooth_velocity、dye_advection 等）

5. 修改 `src/vk_compute.cpp` 的 `RecordFluidStepCommands`
    1. 所有 `fluid_solvers_->SolveXxx(cb, ds, ...)` 调用替换为链式接口：

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    `fluid_solvers_->task_xxx().Begin(cb, ds).PushConstant<T>({...}).End(unit_count);`——无 push constant 的 task 省略 PushConstant，unit_count 为 `cell_count_` 或 `ibm_marker_count_`

6. 修改 `src/vk_compute.h`
    1. `pipeline_layout_` 类型从 `unique_ptr` 改为 `shared_ptr<vk::raii::PipelineLayout>`
    2. `pipeline_layout()` getter 返回类型从 `const vk::raii::PipelineLayout&` 改为 `shared_ptr<vk::raii::PipelineLayout>`
